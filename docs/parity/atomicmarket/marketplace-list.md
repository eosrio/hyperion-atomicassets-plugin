# AtomicMarket marketplace list source controls

The route `/atomicmarket/v1/marketplaces` reads all records of the existing marketplace kind through the optional SDK complete-kind host. It declares the existing projection's `readAttempts`, `responseRecords` and `responseBytes` as the required offer. The host and adapter negotiate those totals; no public pagination, ordering, filter or count is exposed. A missing host or invalid, foreign, or mismatched row fails the request. The existing reducer keeps the first creation block and time across replacements.

`tests/marketplace-list.test.mjs` runs the actual pinned atomicassets-api 2.7.0 HTTP callback and its SQL invocation with a scripted database boundary and compares empty and multiple rows against plugin HTTP. It retains both arrays, compares membership and fields without assuming SQL order, and exercises ignored query and POST body inputs, GET, POST and HEAD, and invalid row refusals. `tests/marketplace-id.test.mjs` independently compares the actual original replacement processor. These controls are not physical PostgreSQL/MongoDB comparison or a managed host acceptance. Actual adapter exhaustion, overbudget refusal, cache-enabled behavior and full AtomicAssets/AtomicMarket 2.7.0 parity remain release qualification work.

The real SDK owner negotiation and `composeStatefulOwnerCompleteKindReadV1` are exercised by `tests/marketplace-list-sdk.test.mjs` through the actual plugin route and a controlled paged adapter adapted from SDK commit `7412889a14c84342551fd864ea3ebfcf28849385`. The adapter requires an explicit empty terminal page; row, byte and native-attempt exhaustion and nonliteral completion refuse. This is controlled source evidence, not physical adapter proof. The same controls were run against the installed plugin tarball on both Node 24 and 26.

The cache-enabled control executes the pinned original middleware with a controlled in-memory Redis port: the original miss, set, expire and hit are observed. It compares the returned membership and fields against two request-scoped plugin responses. The plugin does not implement that Redis cache; host cache reuse, version binding, and publication fencing require managed-host acceptance. A retrospective separate `edfc7a5` baseline returned HTTP 404 on Node 24 and 26 for the list. The baseline script is `tests/fixtures/marketplace-list-baseline-red.mjs` and is run from the root of a separately built baseline checkout.

The first three Node 26 cache-enabled child runs exited with Windows libuv `UV_HANDLE_CLOSING` assertions when the child used a second `fetch`; the successful controls use Node HTTP for the second loopback request. Those failures remain part of the evidence and are not treated as passing runs.
