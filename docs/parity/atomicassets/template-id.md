# Template ID route (issue #53)

The route reads the template, collection and schema through the same request-scoped state host. The reference 2.7.0 handler selects `atomicassets_templates_master` by contract and ID, checks the collection after its inner joins, and passes the row through `formatTemplate`. Mutable metadata is overlaid by immutable metadata. Covered absence returns the original HTTP wrapper's 404; invalid ID returns 400. Unknown coverage, invalid rows, and unsupported numeric forms fail closed. Leading zero IDs resolve to the canonical numeric ID.

The focused controls execute original and current lifecycle processors on the same fixture occurrences and compare the original HTTP wrapper and current request route through a finite modeled SQL view. Its SQL collaborator is not PostgreSQL, and its fixture is not an initialization or source-authority proof. The original cache ignores query strings and serves cached successful bodies until expiry; current plugin has no matching cache implementation in its request-scoped host, so cache parity is unqualified. Physical PostgreSQL/MongoDB comparison, managed host serving, fork/recovery and full API parity remain unqualified. Existing config issue #52 remains pending and is untouched. This change does not authorize deployment or executable updates.
