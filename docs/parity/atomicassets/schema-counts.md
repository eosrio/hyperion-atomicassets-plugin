# Schema asset totals (issue #56)

The projection adds `schema-asset-count`, keyed by contract, collection and schema. Its decimal `assets` total counts asset rows, including burned rows. The asset transition reads the prior asset and affected totals through the same caller-provided staged view and stages count changes with the asset. A replayed upsert and owner-only change leave totals unchanged; moving an asset adjusts both keys. The helper also supports an actual deletion, but this component adds no new delete source or endpoint.

The declaration now requires 21 record kinds. An explicit limit of 20 is refused by the SDK; existing callers and frozen physical fixture declarations are not silently raised. A new generation must be initialized from a trusted complete asset baseline with matching per-asset identity/absence and schema-count coverage, then caught up without a gap. Covered absence of a count means zero only under that generation's qualified coverage; unknown coverage is unavailable. Existing projections need a qualified rebuild or seed and handoff. Current SDK interfaces do not prove that initialization, provenance, recovery or serving has occurred.

Focused controls use original and current lifecycle processors on identical mint, transfer and burn events with a finite storage model; other transition, candidate failure and rollback controls use a caller-owned test stage. They do not execute PostgreSQL triggers, MongoDB, a runtime initialization job or managed host. This slice does not implement schema ID, its SQL `INT` result conversion, list resolution, cache behavior, or qualify full parity. Issue #52 remains pending.
